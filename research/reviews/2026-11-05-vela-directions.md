# Vela: distinct, revisable directions

The former Vela implementation offered one ink/lime/cobalt world. The new implementation compiles two authored art directions for the same six-screen product: Momentum retains oversized energetic hierarchy and rounded planes; Field Notes uses warm paper/charcoal/terracotta, smaller editorial hierarchy, tighter ruled groups, shallow corners and shorter motion. The recorded brief is `examples/vela/DESIGN.md`. Neither direction is a human preference result.

The compiler uses the existing exported context inspector, real Lato font metrics, energy search, semantic palette analysis, motion analysis and handoff replay. Each direction has its own program and generated policy, bound to the current brief identity. Each current bounded beam run explored 1,064 assignments and attempted 210,672 factor evaluations, retained six candidates, then revalidated the chosen handoff. Neither search exhausts its domain. Both use an explicitly deterministic finite-pool selection with zero neural calls. The original Vela model choice remains historical; it is not relabeled as a selection for a changed program.

The platform adapters consume the selected policy for typography, responsive measure/gutters, spacing, corners, semantic colors and springs. Font-based timer-pair and longest-word constraints couple size/tracking to available width. Metric-triggered short labels retain full accessible names. Direction changes retain task/session state; the browser preserves the focused control's viewport anchor where the new scroll range permits and records clamping otherwise. The portable `projectScrollAnchor` equation consumes current post-layout offset plus the before/after anchor displacement, avoiding double application of browser anchoring. This projection is a geometry operation, not an aesthetic metric.
