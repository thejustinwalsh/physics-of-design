# Relay task priority and staged local selection

This is an engineering experiment, not a human preference study. Synthetic Astra critique motivated comparing the incident response action with the fleet summary in the initial task viewport. The editable brief lives in `examples/relay/DESIGN.md`.

The [retained evidence archive](../evidence/2026-11-05-relay-attention.zip) contains the historical 96-cell renderer matrix, successful/failed workflow receipts, actual selector input/output/process records and a per-file SHA-256 manifest. These historical receipts retain their original source identities.

## What was measured and selected

`scripts/measure-relay-attention.mjs` measured six semantic orders in Chromium and WebKit at eight viewport/content/enlargement scenarios: 96 cells. The historical renderer receipt is `artifacts/relay-attention/matrix-7f32525f9e1f/report.json`, matrix identity `8e20c4efe49177e7c7f777764204369fcbf41cd1b8a1afebf9bc4ae886e0902f`. Visibility means clipped region area divided by the region's area. Start/end positions use the task frame's flow extent. Neither quantity measures attention, salience or usability.

The small local workflow preserves separate action exposure, fleet context and diagnostic exposure preferences. Finite-pool initial action visibility filters candidates; an authored 65% action-end target remains soft. Short/enlarged windows can miss that target without losing access to content. Six compositions, 192 kinetic assignments and three already contrast-validated palettes produce 201 numeric assignments; they are not 201 neural decisions.

`scripts/select-relay-attention.mjs` used the actual local Qwen3.5-4B/SemIf selector at three conditioned stages. The successful receipt is `artifacts/relay-attention/choice-1793856188002/report.json`, source identity `55457824ae712427df36104806043930a9bcbcdb9cbc62884c03b1ee509b395e`. It chose Response-first/action-leading, mass 1, stiffness 200, damping ratio 0.85, roughness 0.55, light response 7 and Graphite/Citron. Damping is derived as `2 ζ √(k m)`, approximately 24.04163. These are brief-conditioned alternatives, not aesthetic optima.

The first path took 98.726 seconds, with three searches, 201 assignments, 1,635 factor evaluations and three completed neural readouts. Provider-reported input tokens were 2,884, 2,879 and 1,622 (7,385 total). Exact replay took 1.339 seconds, revalidated 11 retained alternatives with 199 factor evaluations, and used three cache hits with zero search and zero neural calls. These are one-machine observations, not a matched throughput or coding-agent token benchmark. Each stage currently reloads the local model; persistent inference remains an opportunity.

Provider-reported forward times sum to 75.263 seconds of that 98.726-second path. Process reuse alone therefore cannot make this measured path finish in a few seconds. Further prompt reduction and verified inference-backend improvements need measurement; fewer calls are not themselves a latency result. The 201 numeric assignments and the three neural choices have separate costs.

Editing the palette question reuses upstream stages and makes palette stale. Editing a kinetic target reuses composition, makes kinetics stale and blocks palette. Both invalidation probes used zero neural calls. The handoff retains design, matrix, workflow and result identities.

## Failures retained

The earlier actual run `choice-1793855802463` completed composition but rejected its kinetic readout at 4,786 input tokens against the unchanged 4,096 cap. No truncated prompt or substitute handoff was accepted. Across both runs there were five neural attempts and four completed readouts; the successful path alone used three. The shared readout now stores single-scenario factor definitions once and retains exact option values/residuals, units, bands and provenance. Bound predecessor variables include their semantic aliases. Multi-scenario worst-case summaries retain their existing representation. This is not a controlled before/after token benchmark because other context corrections also changed.

Synthetic review also found incorrectly described visibility units and insufficient full variant-definition validation. Both were corrected before the successful run. Renderer facts remain bound to their historical source; applying a handoff requires a new build and current renderer checks.

## Runtime follow-up

The following changes happen after the first preview above. The handoff now supplies the common emitted web/native plot spring. DOM action finishes consume its roughness and elapsed-time light-response rate. The generated palette becomes the initial preference; explicit palette choices remain overrides. Binding validation rejects nonfinite/out-of-domain parameters and contradictory damping. It validates the binding shape, not a selector receipt's authenticity. CSS recipes remain appearance approximations. Native consumes palette roles and an actual native spring; roughness, CSS lighting, GPU planes and variable highlight response remain unsupported there.

An initial adapter build passed 86 Chromium/WebKit checks, including actual intermediate cursor positions, pointer-driven light changes, reduced-motion snapping and zero remaining host-clock work. Synthetic review correctly observed that a fixed toolbar rectangle alone does not prove fixed controls; the revised proof also compares every interactive child's current rectangle. Final current-source results are recorded separately from that initial pass.

Two actual Android failures were retained, both with confirmed cleanup. `android-1793857426392` exposed a driver waiting for a fresh mutation after tapping the already-selected route. `android-1793857711046` then changed the actual chart bucket from 47 to 46 but recorded zero native animation starts and a suspended cursor despite an onscreen measured plot. This was not accepted as native-motion success. A changing parent callback ref cleared the host before the child's layout effect. The fix retains the native View's object ref and bridges compatibility/external refs using imperative handles. A subsequent actual run passed the selected-spring start assertion; its remaining task/scale/dialog checks were still running when this section was written.

Runtime capture also read motion/clock values frozen at React-render time. Explicit captures now sample the live registry and scheduler. Attach/dispose and native start/finish events invalidate inspection without a polling loop. Idempotent disposal is tested. An intentionally suspended native animation retires its generation before stopping so a late callback cannot overwrite its reason. These are synchronous JS diagnostics plus host geometry, not a synchronized native trajectory measurement.

The first local ordered lane completed all 28 stages with stable source but failed its separate Expo toolkit specimen because that worktree's dependencies were missing. Installing its existing lockfile dependencies and rerunning the affected producer passed its 60 checks and Relay static/browser follow-up. The failed ordered record remains failed; a new ordered lane is required for the final runtime source.
