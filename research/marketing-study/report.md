# Design Theory marketing-site case study

November 8, 2026, America/Detroit. Three first deliveries are complete and frozen. External verification and neutral user review are recorded separately. The [live neutral viewer](https://andale-baker-prevention-commands.trycloudflare.com/) provides three interactive pages and optional local rating export. These are temporary Cloudflare URLs.

**The full-toolkit condition used more coding-model tokens than both controls in this case. Visual superiority has not been established.** This is one product and one stochastic build per condition, not a general causal estimate or a preference calibration.

## What was compared

A modern single-page marketing site for Design Theory: simple product explanations, supplied original sculpture imagery, expressive typography, tactile surfaces, parallax, animations, a coupled-choice demonstration, working navigation and a copy-command action. All builders received the same recorded brief, art direction, product facts, neutral React/StyleX scaffold, licensed fonts and artwork. The bare condition received no added design guidance or toolkit. The guidance condition received the short, authored [practitioner-principles document](GUIDANCE.md) frozen for this trial. This is the specific guidance control tested; these results do not benchmark other skill packages. Full received that identical guidance plus the frozen Design Theory toolkit, its operational skill/references, and access to the existing local selector.

The full workflow's extra operational skill/reference material is part of this treatment; this is not an isolated ablation of equations independent of that material. Full was explicitly instructed to use the tools and actual selection/replay. This does not measure spontaneous tool discovery. Bare means the ordinary coding-agent harness, not a foundation model stripped of standard system instructions.

All actual builder threads reported GPT-6.1 Sol, high effort, default service tier, Codex CLI0.164.0. The configured/reported model slug was held constant; provider weight revisions and sampling seeds were not returned/pinned. Fresh workspaces lived outside repository AGENTS inheritance. Host skills/MCP/plugins/memories were suppressed and actual prompt diagnostics checked. The [isolation audit](isolation-review.md) found no observed boundary violation and verified every immutable input and frozen source identity. Isolation is instruction plus trace audit, not complete OS read denial. Randomized sequence was guidance, full, bare. There was no imposed deadline or token cutoff, no human repair feedback and no access to sibling outputs. Each first final delivery was frozen immediately after owned process cleanup.

## Local selector and tool influence

The full condition has two actual wrapper process attempts: one exit1 and one exit0. Successful provider input is 984 tokens on Qwen3.5-4B Q4_K_M, checkpoint SHA256 `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`. The restricted-option readout generates no text. Input usage for the failed attempt is not established. Observed wrapper durations are 11.675 and 14.989 seconds. These local-model counts are kept separate from coding-model tokens and are not pooled as interchangeable cost.

The read-only [tool influence audit](tool-influence-review.md) records exactly which authored inputs, numeric choices, selection, replay and renderer observations affected the implementation. Its scope matters: selected desktop values are not proof that every mobile/tablet relationship came from the engine. Search estimates must not be described as renderer facts. Zero-call replay demonstrates reuse of a saved decision path; it does not establish end-to-end token savings or beauty.

The successful numeric path searched 21 states (33 including the failed attempt), then replayed six retained assignments with two cache hits and zero new searches/readouts. It was a genuine dependent two-stage workflow, but not a large adaptive design tree. The numeric workflow still declares renderer verification pending; separate browser measurements were not fed back to revise or select the recipe. Size alternatives collapse to the same phone/tablet output through authored overrides, while some leading still carries through. The demo's save/replay buttons restore an illustrative slider preset; they do not execute the engine recipe.

Most composition, palette, material appearance and motion were directly authored. This is evidence that the tested workflow only delegated a narrow typography decision, despite broad tool availability. It suggests investigating handoff coverage, meaningful preference factors, compact tool context and renderer feedback before assuming that more local-model calls or model training will solve the efficiency problem. That is an engineering hypothesis, not a demonstrated causal explanation of the token difference. Musical priors were not isolated in this comparison.

A coordinator interim monitor mistakenly counted receipt directory entries as invocations. That was corrected publicly: top-level input/output/process files are not separate model calls. The final ledger counts actual invocation.json directories and associates provider rows by observed row IDs.

## Shared costs and evaluation status

Shared setup is outside the per-builder table. The recorded common model/browser capability smoke used 46,864 coding-model tokens. Artwork creation, environment provisioning, coordinator/subagent orchestration, review and evaluation are not fully accounted in that figure; they are not zero. The toolkit/model/dependencies were already provisioned. This study therefore does not establish an all-in project/setup cost advantage.

The main external matrix is Chromium and WebKit at ten viewport sizes, normal/reduced motion, wheel/anchor/keyboard/copy actions, separate computed-text-size and changed-heading probes, imagery/font diagnostics, resize and intermediate motion frames. A separate control probe tests continuous pointer movement and keyboard controls at phone/tablet/desktop where supported. These are renderer/interaction observations, not aesthetic scores or full WCAG/physical-device certification. The enlargement probe doubles the pre-mutation computed font size of each text-bearing element with an inline override. It is an authored stress probe, not root-font scaling, physical browser zoom or native Dynamic Type.

**External result status: complete.** The unchanged main evaluator completed all 60 cases with zero incomplete runs or infrastructure errors. Each condition had 20/20 initial layouts without horizontal page overflow, working wheel scrolling in both directions, zero page errors and zero local HTTP errors. All visited reduced-motion content remained visible. This is sampled browser evidence, not proof for every possible viewport or content string.

## Evidence and repeatability

The protocol, common brief/content/direction/guidance, artwork/font provenance, runner, independent evaluator, control probe, accounting and viewer tests are retained in this repository. Actual receipts and frozen builds are under `/private/tmp/design-marketing-20261108-b`. The portable sanitized [core archive](../evidence/2026-11-08-marketing-study.zip) and all image parts listed in its [archive index](../evidence/2026-11-08-marketing-study.json) retain source, builds, receipts, failures, browser observations, images and harnesses. Extract them into the same directory. Each archive entry is read back and SHA256 checked after packaging; the external index records archive hashes. Private prompt/config bytes and account events will not be published. Archive manifests distinguish original from sanitized hashes. Frozen outputs retain exact bytes, including any authored runtime paths; public run metadata uses documented path placeholders. The resulting static sites run without Design Theory or Qwen at runtime; source recipe replay additionally requires matching toolkit/model provision and rebinding recorded paths.

A post-browser recheck recomputed all 212 frozen-file and 28,520 immutable-input hashes without mismatches. An initial coordinator-only checker mistakenly treated nested directory hash maps as files and failed; the corrected recursive checker and correction receipt are retained. This did not affect any builder or renderer.

The original setup trial-a had no design builders: sandboxed diagnostics failed and a generic quoted skills heading caused a false-positive isolation rejection. These setup failures were preserved; the corrected runner prepared fresh trial-b before any design builder launched. The evaluator's root-origin hosting amendment prevents artificial subpath asset failures and preserves the prior evaluator version. The protocol and pass criteria were unchanged; no builder output was inspected to choose that amendment.

The narrow conclusion already supported by the completed usage receipts is a token regression for the tested full workflow. Any claim that it produces better designs still requires actual preference/task evidence. Keep engineering functionality, selected-property influence, replay reuse and aesthetic benefit separate.
