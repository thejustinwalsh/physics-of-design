# Design Theory marketing study — shared product brief

Recorded November 8, 2026. Source: user's request for an isolated bare-model / guidance / full-system test of a modern marketing site for the system itself, with simple explanations, features, strong imagery and animation, and a single-page parallax scroll experience. The following creative decisions are authored study assumptions, not interview answers or human preference evidence.

Build a complete single-page marketing site for **Design Theory**, the local-first toolkit previously called Physics of Design. Audience: developers and designers who use coding agents and want expressive interfaces whose decisions remain editable and measurable.

Use CONTENT.md for accurate product facts and approved copy. You may tighten connective copy and choose headings while retaining all feature meanings and the evidence boundary. Aim for short, confident, human prose. Explain what visitors can do and show it visually. Do not present formulas as proof of beauty or claim measured token savings, award wins or validated aesthetic superiority.

Creative direction is in DESIGN.md. Heavy visual storytelling is essential: real supplied campaign imagery, original procedural/vector compositions if useful, typography, tactile surfaces, scroll-linked parallax and purposeful transitions. The site should feel like a designed product launch, with a coherent beginning, middle and invitation. This is not a documentation page or an inspector/dashboard. Avoid filling the screen with small cards or implementation diagnostics.

Required visitor journey: understand the promise in the first screen; explore the feature story; understand brief → explore → measure → save/reuse; interact with at least one meaningful small demonstration of coupled design choices; reach a working get-started section and repository link. Include navigation anchors for Features, How it works and Get started (labels may vary if their meaning remains clear). Include a real local 'Copy command' action and visible success/failure feedback for `npm run build`. That is a source-checkout build command, not a published npm install promise. Primary external CTA points to https://github.com/thejustinwalsh/physics-of-design . Use no fabricated signup/backend.

Output React + StyleX, flex-based layout (no CSS grid). Ordinary CSS may handle font faces, keyframes and complex effects. GSAP, Lenis, Three, colorjs.io, Canvas and SVG are available equally; choose what serves the page. Use actual local fonts and supplied original artwork. No external assets, package downloads, web research, image generation or other coding agents during this build. New code-native imagery is allowed equally. No prior implementation source or prior study output is available/permitted.

Support continuous window resizing with natural reflow and scrolling at any positive size; samples are not viewport admission limits. Verify phone, iPad/narrow window and desktop. Content must survive changed text and user enlargement. Preserve keyboard navigation, meaningful focus, legible contrast and alt text. Prefer native scroll; any smoothing must retain keyboard/touch/access to every section. Reduced motion keeps all content and meaningful interactions available with spatial parallax removed or simplified. Keep controls stable; pause hidden/offscreen work and dispose listeners/RAF. Be mindful of WebKit/Safari performance. Do not claim physical-device verification from emulation.

Build and self-test until your first delivery is ready; there is no wall-time or token budget. Do not ask interview questions: shared authored assumptions are frozen. Leave public/index.html, executable source, BUILD-REPORT.md and any honest test receipts. Build with npm run build. Report what works, what failed, what you did not verify and which assistance you actually used. The first final response ends the build; no post-delivery repair or background mutation.
