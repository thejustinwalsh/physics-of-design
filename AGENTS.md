# Design Theory repository workflow

For UI specimens, galleries, app demonstrations and design-rule experiments in this repository, activate [.agents/skills/design-theory/SKILL.md](.agents/skills/design-theory/SKILL.md). Read only the relevant facet references. Preserve the requested art direction; the toolkit must support multiple styles.

Begin with a recorded brief. When the user asks for simulated interview answers, label the respondent synthetic and retain the questions, answers and assumptions. Never turn them into human preference evidence.

Use the existing CLI/MCP or its exported implementation functions to generate and inspect choices. Keep an execution trail that distinguishes authored inputs, numeric exploration, model selection, renderer measurements and replay. A model confidence or a displayed equation does not verify a design. A saved control preset is not a solver recipe.

Direct manipulation must keep controls stable. Validate real continuous pointer and keyboard interactions, current DOM geometry, phone/iPad/desktop reflow, changed text, reduced motion and disposal. Tie inspection overlays to the actual rendered element and current input identity. Improve shared equations and adapters when critique reveals a failure.

Default MCP discovery stays compact: fetch one schema, use result references, and keep full receipts outside model context. Run affected checks and the ordered verification lane before publication. Report what failed and what remains unverified; preserve historical evidence as historical.
