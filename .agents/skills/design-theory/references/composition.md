# Complete compositions

Use a concrete product, actual content and complete task states. A title/prose specimen cannot establish composition quality. Preserve separate publication, reading and app task goals.

`composition plan` supplies editable measures, density, type and flex topology. `composition analyze` accepts rendered rectangles and explicit peer alignment constraints; only comparable semantic roles should be aligned. `cropMedia` computes authored-focal-point cover geometry shared by web/native. A detected alignment failure should refine the reusable frame/role constraint before local decoration.

Native work uses Apple source IDs from `registry` and `platform audit`: actual safe insets, labeled targets, uncancelled Dynamic Type, stable destinations and preserved task state. Keep default versus minimum target sizes distinct. Missing measurements stay unknown. Do not claim that custom React Native primitives reproduce UIKit materials or that rectangle checks establish full HIG conformity.

Review whole rendered views at phone, narrow tablet window, iPad and desktop as applicable. A native app needs actual native evidence, task-specific navigation and working flows; mobile web is insufficient. Exercise Back/Forward, search/empty, save/remove, reading resume, appearance and large-text states. Preserve project/criterion identities and label Astra judgments as synthetic.

Consult `docs/skill-comparison.md` and `research/design-rule-candidates.json` only when selecting practices. Treat fixed scales, named-font bans, mandatory gradients/reveals, color harmony and musical landmarks as optional authored priors. Never fabricate proof numbers, awards or usability results. Read `docs/apple-hig-mathematics.md` for scoped platform checks and `docs/fieldwork-design-review.md` for distinguishing full-composition findings.
