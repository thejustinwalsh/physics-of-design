# Fast composition spell

Use this when the brief is known and many coupled numeric choices should become an executable design policy. `composition solve` is the high-level entry point; discover its schema only when needed.

1. Preserve product intent, actual content, visual direction, platform requirements and licensed fonts. Interview only material gaps. Author meaningful screen/task priorities and responsive copy equivalents explicitly; never silently substitute user content.
2. Define finite editable domains, derived expressions, hard constraints and brief-scoped preference bands/weights. Tag every factor as measured/calculated, standard, heuristic, hypothesis or brief. Nonzero tension targets and multiple wells are valid. Musical landmarks are optional.
3. Run bounded mathematical search. Keep its choice graph and individual factors by result reference. A mathematical proposal is not a renderer receipt. Use `energy analyze` when the direction of a coupled change is unclear; its finite differences can cross discontinuities.
4. Use `decision run` for explicit conditional stages: repeated bounded mathematical searches, optional local SemIf readouts on narrow frontiers, predecessor bindings and per-stage cache identities. `composition solve` retains its single-readout mode. Keep neural inference outside the hot mathematical loop. It must not verify facts, issue accessibility judgments or convert option logits into aesthetic confidence.
5. Give the build agent the resolved handoff: selected values, alternatives, copy, responsive region bindings, transitions and motion rules. Reuse `decision-runtime` on web/native. Implement React + StyleX and RN flex layouts, preserving natural text height and user enlargement. The machine is a contract, not an arbitrary component compiler.
6. Replay a matching machine without inference. A solver recipe also binds search/readout options and checkpoint bytes. New brief/factors/domains/content/topology or failed runtime guards require new search. Never trust cached feasible flags.
7. Verify finalists in actual browser/native renderers. Check phone/iPad/desktop, changed content, large text, task flow, focus, persistence and reduced motion. Geometry containment does not establish task accessibility: an action buried below a promotional heading can still fail the brief.
8. Convert critique into shared relationships and topology. Prefer semantic heading roles, action priorities, navigation-fit rules and structural reflow to local pixel patches or suppression of text scaling.

Measure actual native roots and project physical safe areas before resolving the usable viewport. Nominal window metadata is not the content root. Before evaluating expressions, check declared input applicability: even positive transient dimensions can invalidate a fitted size or logarithm. Record rejected inputs and explicitly label unavailable/unsupported geometry or a held previous layout; recover valid geometry without losing session state. Expand and reverify the problem contract when the brief needs additional window ranges. Never mask arbitrary evaluator errors or call a held receipt current.

Use `palette candidates` for joint token repairs; `palette analyze` preserves role/state/adjacent-surface checks and alpha uncertainty. Unknown backdrops cannot pass. Use `motion analyze`/`motion emit` for analytic springs and platform limits. Use `component solve`/`component inspect` for exact anatomy dimensions and drawings from the same contract; missing ink or stale text measurements remain unknown. `design_specimen` can project component/motion inspections in its optional MCP App.

The executable Vela example is `examples/vela/problem.json`; its authored policy and complete app are a proof, not a universal style template. See `docs/adr-002-fast-design-machine.md` and `docs/design-machine-report.md` for measured costs and open claims. No award-level quality, trained taste or token savings may be inferred from energy or synthetic critique.

`decision run` executes one chosen DAG path, retains alternatives and revalidates cached assignments. It does not automatically backtrack through the whole DAG. Optional bounded direct-successor lookahead can require a witnessed continuation and prefer successor targets among exact parent factor ties; unknown/incomplete branches stay explicit. Child-policy changes also invalidate a parent whose choice used that lookahead. Model bytes are hashed once per prepared run; unchanged stages replay without inference. Changed context, source, domains, options or model identity invalidates affected entries. Inspect separate neural/test/attempt/completed counters; mathematical evaluations are not neural calls. See examples/workflow/editorial.json and docs/decision-workflow.md.

Use `validation plan`/`validation check` for a separate XState phase gate. Author required viewport, text-scale, motion, content and platform scenarios and tools before progression; keep exact current design/plan/input identities and result references. Missing, stale, failed and unknown receipt declarations block. Synthetic critique cannot satisfy human review. Unsupported support may advance only under explicit authored record policy and remains reported. The gate coordinates caller evidence, not authentication or tool execution. See docs/validation-phases.md; keep the matrix scoped to the actual brief.

For a concrete finite coupled case, use `field measure`, `field run` and `field validate` (docs/design-field.md). The case combines actual text matrix cells, bounded successor exploration and two optional local frontier choices. A matching path revalidates saved alternatives and successor witnesses without new search or inference. Bind DESIGN.md separately from reusable text/font measurements. A changed reading choice invalidates conditioned expression choices; edited UI alternatives are previews until their exact finalist is measured. Keep numeric evaluations, actual neural readouts, cache replay and rendered validation as separate counters.

Runtime scenario bands must match the actual named input vector. Ambiguous hard applicability blocks; unsampled hard overrides require a declared policy. Pass semantic units/complete category aliases to System1, with worst-scenario residuals and applicable bands. Preserve Pareto/diversity diagnostics, genuine ties, infeasible targets and comparison-budget exhaustion; never add arbitrary jitter to create a score spread. See docs/adr-005-bounded-successor-lookahead.md and docs/adr-006-scenario-applicability-and-selector-vocabulary.md.
