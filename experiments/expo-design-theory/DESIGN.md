# Expo Design Theory interoperability spike

## Brief and provenance

A deliberately small instrument for reviewing three observation records. The user requested one or two Expo Web tuning rounds before Relay and actual native iOS/Android proof with React Native primary. This is an integration experiment, not the Relay product or evidence of cross-platform visual parity. The respondent and reviewer judgments are synthetic unless explicitly stated otherwise; no human interview is fabricated.

## Task and direction

Filter All / Needs review, open a record, inspect details, mark reviewed and return to the list. Keep the filter and selected record stable through density and viewport changes. Quiet warm substrate, dark ink, acid accent, and clear hierarchy support the information; native uses static finishes. The existing GPU material shader remains web-only and is not required for this spike.

## Shared design decisions

Use React Strict DOM/StyleX flex primitives if the current packages compile and render on Expo SDK58, React19.3 and RN0.88. Typography, density and responsive region choices come from recorded Design Theory implementation outputs. Render actual content without truncation, preserve user enlargement and touch targets, and inspect current component bounds. Explicit native fallbacks must name the unsupported feature and retain the shared decision inputs.

## Acceptance and limits

Web: actual Chromium/WebKit phone390, iPad820, desktop1440 widths; changed text and enlargement; native keyboard/pointer controls; list/filter/detail/save states and current rectangles. Preserve round1 failures and round2 corrections. Native: actual iOS/Android Expo Go or development runtime, native primitives and geometry receipts, core flow state transitions and screenshots; no WebView evidence. Physical hardware energy use, full accessibility conformance and a native material shader remain unverified.
