# Relay — substantive tool use and evidence contract

Before native execution, read [PLATFORM-RUNTIME.md](PLATFORM-RUNTIME.md) and the actual host tool paths supplied in BUILDER.json. Reuse the provisioned drivers with private writable receipt directories.

This is an authored coverage obligation, not a claim that calls or validation have happened. Use the same policy for Luna, Sol and Astra. Root owns the executable experiment policy/harness; this document names required relationships and outputs. Discover one command schema through the compact catalog when needed, use exact result references, and keep full receipts on disk. Meaningful affected tools are required; ritual calls to every command are not.

## Output influence and source trace

Each coverage record includes builder/platform/scenario/surface ID; tool+exact input hash; current DESIGN/brief/fixture/source hash; result reference; authored versus calculated versus model-selected versus renderer-observed evidence class; selected output JSON pointer; target token/component property and source location; rendered element/native test ID; and current renderer receipt. A source import without a consumed output is insufficient. Calls against irrelevant sample copy or an unused color cannot satisfy this contract. A receipt claiming a source hash that did not render is stale.

| --- | --- |

## Validation phase matrix

| Phase | Obligations before advancing | Evidence boundary |
| --- | --- | --- |
| 0 — freeze | exact common brief/design/fixture/assets/font provenance; platform versions and Expo/RSD/style integration smoke; no UI divergence | authored inputs + package/build observations |
| 1 — choices | stage predecessor bindings, meaningful candidates/perturbations, selected output property bindings for twelve surfaces, matching replay | actual tool outputs; model choices stay synthetic |
| 2 — Expo web tuning | one or two documented tuning rounds, same feedback policy; phone/320/narrow/iPad/desktop/wide; light/dark, enlarged/changed text, chart cursor and real pointer/keyboard controls | current browser geometry/composites/screenshots, no native parity claim |
| 3 — native primary | actual iOS and Android run; measured safe content roots/text and rotation; primary diagnosis flow + rule/settings/recovery; native touch/hardware keyboard where available; every unsupported feature recorded | actual native observations/screenshots; simulation versus physical device labeled |
| 4 — robustness | full functional primary/secondary flows, storage failure, reload/local persistence/reset, offline/loading/empty/error retry, long content, reduced motion, disposal/hidden work; asset/license/source identity | passing current receipts for each named obligation; no historical substitution |
| 5 — review/publication | independent synthetic architecture/visual review as requested, independently verified findings, all required phase receipts current; affected checks + ordered verification lane | failed/unverified reported; no human/award/token claim manufactured |

Do not multiply every scenario mechanically: declare a justified matrix covering every platform/viewport/state obligation with risk-specific intersections (for example phone + long text + native enlargement, desktop + dark + full waterfall). A missing Android flow or iPad geometry remains missing even when other cells pass. Re-run affected cells after any change. Preserve the failed receipt and correction trail. Hardware-only sensors/Safari performance may be explicitly out of scope and remain unverified; core native flow support cannot be waived as an unsupported decoration.
