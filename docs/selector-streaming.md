# Local selector execution and progress

The local selector runs until the provider exits or the caller cancels it. There is no elapsed-time cutoff and no timeout configuration. Prompt token limits, finite candidate domains, and existing search/readout bounds still apply. A provider result larger than 16 MiB is preserved as a file and rejected before JSON parsing; raw stdout and stderr stream directly to files without a memory-sized output buffer.

Node callers can pass `SelectorExecutionOptions` with `signal` and `onProgress` to `selectLocalOptions(request, execution)`, `prepareLocalOptionsSession(gguf, execution)`, `selectChoice(request, renderer, execution)`, and `runDesignField(input, execution)`. Prepared sessions inherit those hooks and allow overrides on `session.select(request, execution)`. Workflow callers use `runDecisionWorkflow(input, testHooks, execution)` or `compileDecisionWorkflow(input, testHooks, execution)`, preserving the existing second argument. Execution hooks are not JSON input, prompt content, cache identity, or preference evidence. Observer exceptions cannot change the selection.

Progress events contain a fixed phase, its process/provider origin, and optional declared row ID and token counters. The parser drops unknown phases, undeclared rows, malformed records, nonmonotonic counters, totals exceeding the declared prompt limit, and extra fields. Oversized lines remain in the raw stderr file but are not interpreted. Receipts retain only the latest event and event count, not an expanding event history.

The repository adapter `scripts/semif-progress.py`, invoked by `scripts/semif-local.sh`, observes the installed llama.cpp backend. It reports model loading, row start, and the number of input tokens whose native `llama_decode` chunks returned successfully. A chunk in progress does not advance the count. The wrapper restores the native function even on failure and does not alter prompts, logits, option scores, or selection policy. It reports no ETA, generated tokens, confidence, aesthetic score, or visual verification. Other provider executables may supply no progress; their raw pipes and process lifecycle are still streamed.

An `AbortSignal` terminates the spawned process group on POSIX, including inherited children. Processes that ignore termination receive a forced kill after a one-second shutdown grace. That grace begins only after explicit cancellation or a pipe failure; it is not an execution deadline. Workflow cancellation stops later stages. On Windows the implementation requests `taskkill /T /F`; the Windows branch has not been exercised by these macOS tests.

Each attempted readout stores input, stdout, stderr, any complete or partial output, and an exact process receipt. Failed/cancelled attempts also store a bounded failure receipt. With an explicit audit directory these files remain there; otherwise a failed run retains its temporary diagnostic directory and identifies it in the error. Successful temporary files are removed. Output validation still checks declared rows, option IDs, probabilities, backend, revision, and checkpoint digest before returning a choice. Process completion alone is not a valid readout.

## Executable evidence

The actual 2026-10-25 run in `artifacts/design-field-streaming-selector` emitted 35 progress events, including completed native chunks through 4,506 and 3,733 input tokens. Both processes exited 0 with `wallTimeLimit: null`; the two readouts took approximately 79.22 and 62.21 seconds on the recorded CPU setup. The field explored 3,132 numeric assignments, passed all six standalone finalist renders, and replayed without search or inference. Source and emitted-module hashes, including the Python wrapper and process helper, matched before and after execution. These observations prove installed-backend progress and reuse for this case; they do not establish decision quality or a general latency advantage.

`npx tsx --test test/selector-process.test.ts` uses synthetic Node provider processes and a Python native-call stub. It checks progress delivery before a provider completion marker, streaming a diagnostic larger than the former buffer, ignored legacy timeout configuration, cancellation during prefill with a child that ignores SIGTERM, retained partial output, workflow propagation and unchanged replay identity, and exact failed-output preservation. The Python stub checks completed chunk counts and restores the original decode function after a failed chunk. These tests execute no model and do not establish model latency or selection quality. A fresh actual-model receipt is required to establish progress from the installed native backend.
