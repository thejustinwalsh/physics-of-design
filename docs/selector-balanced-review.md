# Adversarial review: balanced selector readout v2

Verdict: accept as an explicit engineering diagnostic after the protocol checks below. Canonicalization can make requests invariant to caller array order; cyclic rotations balance answer-slot occupancy. Neither establishes aesthetic validity, unbiased preference, or repeatable inference on a nondeterministic backend. This reviews the proposed algorithm and the existing single-row adapter, not a completed v2 implementation. No production source or original v1 predictions were changed.

For N viable candidates, define a canonical, locale-independent ordering of unique stable IDs. Construct N cyclic rotations. Match each returned probability to its semantic candidate ID and compute `s(i) = (1/N) * sum_r log(p_r(i))`; select the largest score, applying an explicitly specified deterministic tie policy. This ranks geometric mean support, not arithmetic mean probability. The rows are correlated views from one model, not independent samples or votes. The normalizing denominator in each row contributes the same additive log term to every candidate, but candidate/context interactions can still change ranking.

Priority checks:

1. **Canonicalize the entire request.** In the inspected single-row adapter, `state.candidateHashes` is constructed from caller-ordered `verified`; sorting only `options` leaves a leak. Canonicalize every prompt-bearing candidate sequence and the candidate/state/evidence associations before deriving row IDs. Keep content, criterion and measurement evidence identical across rotations; only the intended option order changes. Pin comparator semantics rather than relying on locale-dependent sorting. Include algorithm version, readout mode, widths, text scales, model/checkpoint, token budget and relevant content/evidence in the request identity. A request ID based only on base states can collide across distinct stress scenarios.
2. **Handle zeros deliberately.** Prefer an adapter that transports finite log-softmax values directly, avoiding probability underflow. If only probabilities are available, document `log(0) = -Infinity`: a candidate with any zero has a veto under geometric aggregation. Never let subtraction such as `-Infinity - -Infinity` produce an accidental comparator result. If every aggregate is `-Infinity`, return a readout failure/unavailable result; a lexicographic winner would conceal unusable evidence. If flooring probabilities is chosen instead, version and disclose the floor because it changes the estimator; do not silently substitute `Number.EPSILON`. Reject negative, nonfinite, out-of-range and malformed probabilities and invalid row sums.
3. **Validate the complete batch before selecting.** Require exactly N expected, unique row IDs; reject missing, duplicate, extra or malformed rows even when some are valid. Bind each row to its expected rotation, candidate ID set/mapping, model source/revision, GGUF hash and expected readout contract. Output line order need not match request order if row IDs are used correctly. Require a well-formed prompt hash and verify it against the actual serialized prompt when the protocol makes that derivable; an unverified returned hash is provenance metadata, not proof of prompt identity. Fail closed on process failure or partial output. Do not silently fall back to one rotation.
4. **Keep semantic IDs out of model-visible meaning when possible.** Stable IDs can encode “winner”, “left”, training identity or arbitrary label preferences. Anonymous, uniform answer labels with an external semantic mapping reduce that channel; canonical IDs can remain outside the prompt. Candidate hashes and review labels need not be model-visible. Canonical sorting ensures caller-order invariance for fixed IDs, not invariance to renaming IDs. Renaming can change the cyclic neighborhood and any visible identifier content.
5. **Specify tie and numerical behavior.** Accumulate in a fixed order with adequate precision. Exact ties need a locale-independent ID tiebreak; any near-tie tolerance is an explicit numerical policy, not a confidence threshold. A pure answer-slot fixture should produce equal candidate aggregates after balancing, subject to declared numerical tolerance. Small perturbations can change near-tie winners, so do not claim repeatability merely because the API exports one deterministic ID. Record the aggregation and tiebreak policy without exporting a calibrated confidence claim.
6. **Bound and isolate execution.** Apply the balanced limit to the viable set and explicitly reject more than six viable candidates rather than silently truncating or changing mode. Zero/one viable candidates bypass inference as before. Multiple JSONL rows in one process avoid repeated model loading, but require independent prompt context per row; cached conversational state must not accumulate. Process timeout/output bounds should account for N rows. Ensure token budgeting does not silently truncate candidate descriptions or later options. Verify state/font/checkpoint identity remains bound to the measurements and inference; a path hashed before a concurrent replacement is not a guaranteed loaded checkpoint.

N cyclic rotations are N prompts, not N! permutations and not an exponential search. For N=2 they cover both orders; for N=3 they cover 3 of 6; for N=6, 6 of 720. Each candidate occupies each slot once, but most relative neighborhoods and reversals remain untested. If each prompt contains all N descriptions, serialized option material grows roughly as N squared. Equal slot occupancy cancels a simple additive slot term in log scores under a restrictive model; it does not cancel arbitrary semantic, adjacency, first-impression, contextual or ID effects.

Renderer feasibility means the candidate passed scoped measured checks for the supplied scenarios. It does not follow from SemIf probabilities or selection. Readout repeatability means the same defined input produces the same selection under a stated runtime; it does not mean the selection meets a visual criterion. Preserve both claims independently, including tested widths/scales and backend provenance. No raw restricted-option probabilities should appear as public confidence or design validity; restricted audit artifacts may retain them for reproducibility if clearly marked uncalibrated.
