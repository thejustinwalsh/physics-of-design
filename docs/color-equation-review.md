# Adversarial review of color and composition equations

This review distinguishes exact computations, declared applicability, search behavior, and design interpretation. It uses independent synthetic cases and the reviewing model's qualitative judgments. It contains **no human validation, aesthetic ground truth, usability study, or calibrated beauty score**. Ratings mean **retain** (appropriate within its stated scope), **tune** (useful with a narrower contract), **discard** (the proposed interpretation is invalid), or **insufficient** (the evidence does not establish the claim).

Reviewed implementation: `src/color.ts` and `src/composition.ts`, with opaque sRGB tokens and authored roles; hard WCAG contrast thresholds; OKLab/OKLCH descriptors; soft hue-pattern preferences; bounded accent candidates; and measured rectangular composition descriptors. Source hashes, expected judgments, and observed results are preserved in the probe artifacts below.

## Equation judgments before implementation

| Equation or rule                                               | Model judgment | Required interpretation                                                                                                                                     |
| -------------------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| sRGB linearization, relative luminance, contrast ratio         | **Retain**     | Deterministic color-pair arithmetic, with an explicit opaque sRGB input domain.                                                                             |
| AA/AAA text and meaningful nontext thresholds                  | **Retain**     | Apply to declared uses; never round before comparing. A role label does not establish actual rendered applicability.                                        |
| Decorative role with no contrast threshold                     | **Tune**       | Exempt from this contrast constraint, not proof of legibility or permission to label functional information decorative.                                     |
| OKLab/OKLCH lightness/chroma/hue                               | **Retain**     | Descriptors, not perceived salience or semantic identity. A null powerless hue is necessary.                                                                |
| Analogous/complementary/triadic distances                      | **Tune**       | Authored soft preference only, requiring genuinely distinct chromatic support and explicit circular geometry.                                               |
| Hue-pattern score as overall harmony, quality, or beauty       | **Discard**    | Color roles, proportions, texture, task, culture, and context remain unmodeled. A perfect angular relation is not a design verdict.                         |
| Separate chroma/lightness preference distance                  | **Retain**     | Report the target, normalization, and provenance. Avoid silently trading hard contrast against closeness to a preferred appearance.                         |
| Accent-only bounded search                                     | **Tune**       | Search is an option generator. Empty output means no candidate found under the supplied bounds, except where a separate proof establishes infeasibility.    |
| Chroma-reduction gamut mapping                                 | **Retain**     | Defined local mapping, not a guarantee of optimal perceptual match or identity with a browser's gamut mapping algorithm. Quantized output must be rescored. |
| Alignment and edge-gap distances                               | **Retain**     | Geometry with named edges, units, reference axes, and declared grouping. Zero distance need not be desirable.                                               |
| Area-weighted box centroid                                     | **Tune**       | A centroid of supplied boxes, not occupied-union centroid, visual balance, or attention. Nesting can double-count.                                          |
| Viewport-clipped rectangle union / empty area                  | **Retain**     | Fraction of supplied geometry, not perceived whitespace; opaque containers must not silently masquerade as content ink.                                     |
| Overlap count                                                  | **Tune**       | Detect geometric intersections; do not infer occlusion or defect without stacking, nesting, and semantics.                                                  |
| Reading-order geometry                                         | **Tune**       | Needs declared writing direction and flow. Top-to-bottom/left-to-right ordering cannot judge all interfaces.                                                |
| Supplied prominence descriptors                                | **Retain**     | Preserve attribution to caller/model; do not relabel as measured visual salience.                                                                           |
| A universal ideal spacing, area, symmetry, or whitespace ratio | **Discard**    | No supporting human evidence; responsive geometry and task intent can favor different arrangements.                                                         |

## Independent scalar cases

The standalone oracle in `artifacts/review/color-equations/reference-oracle.json` uses the piecewise sRGB transfer function, luminance weights 0.2126/0.7152/0.0722, and `(lighter + 0.05)/(darker + 0.05)`. It does not import either implementation module. These establish arithmetic expectations, not aesthetic ratings.

| Case                                                 | Oracle observation                                                      | Expected qualitative rating                                                                   |
| ---------------------------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `#767676` on white vs `#777777` on white             | 4.54222496 vs 4.47808945                                                | First passes AA normal text; second fails, even if displayed as 4.5.                          |
| `#595959` vs `#5a5a5a` on white                      | 7.00472921 vs 6.89692622                                                | First passes AAA normal text; second fails.                                                   |
| `#949494` vs `#959595` on white                      | 3.03346983 vs 2.99534614                                                | First passes the 3:1 threshold; second fails.                                                 |
| Same text accent against both black and white, AA4.5 | Feasible luminance interval `[0.175, 0.183333…]`; `#757575` passes both | A sparse search can miss a feasible solution. Reject an unsupported “impossible” conclusion.  |
| Same text accent against black and white, AAA7       | Requires luminance ≥0.30 and ≤0.10 simultaneously                       | Provably infeasible for one opaque sRGB color under both roles; report a constraint conflict. |
| Failing locked ink/canvas, editable unused accent    | Accent edits cannot change the failing pair                             | No candidate can repair that specific invariant pair; identify the implicated roles/tokens.   |

WCAG thresholds are inclusive, and ratios must not be rounded before comparison. The role-dependent text thresholds and large-text size/weight applicability come from [WCAG contrast minimum guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html); enhanced text thresholds and relative luminance are specified by [WCAG 2.2](https://www.w3.org/TR/WCAG22/#contrast-enhanced). Meaningful nontext cues are checked against adjacent colors, with relevant exceptions; “every nontext color pair must differ by 3:1” would be an overclaim. See [nontext contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## Adversarial cases and expected interpretation

| Case                                                                   | Expected behavior                                                                                                    | Model judgment                                                                    |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| All grayscale, or one chromatic accent plus neutral ink/canvas         | Neutral hues null; multi-hue preference insufficient, never perfect harmony inferred from absence                    | **Retain** descriptors; **insufficient** hue-pattern claim.                       |
| Several token names resolving to the same red                          | Deduplicate actual colors/hues before deciding sufficient support                                                    | **Discard** alias-count evidence of triadic or complementary structure.           |
| Hues 359° and 1°                                                       | Circular separation 2°, not 358°                                                                                     | **Retain** wrap-aware distance.                                                   |
| Red/orange/brown with nearly equal hue, different lightness            | Multiple distinct colors but not three distinct angular supports                                                     | **Tune** support definition; color uniqueness alone is insufficient.              |
| Two approximately complementary hues labeled triadic                   | Triadic result unavailable, rather than a low-confidence numeric score presented as valid                            | **Insufficient** support.                                                         |
| Hue rotated by full turns or tiny numerical neutral chroma             | Identical chromatic relation; powerless hue cannot acquire significance from floating-point noise                    | **Retain** normalized angles/null hue.                                            |
| Eight-digit hex, four-digit hex, named transparent, CSS alpha function | Explicit rejection in an opaque-only contract; never drop alpha silently                                             | **Retain** narrow domain.                                                         |
| Large role attached to 12px regular text                               | Arithmetic may be correct, applicability unverified or wrong                                                         | **Discard** claimed WCAG conformance for the rendered text.                       |
| Out-of-gamut proposed OKLCH color                                      | Gamut-map, quantize to actual hex, and re-evaluate every role, lock, descriptor and candidate distance from that hex | **Retain** only actual emitted-color results.                                     |
| Different proposals quantize to the same hex                           | Deduplicate candidates; report fewer alternatives                                                                    | **Tune** diversity claims.                                                        |
| Locked accent, or all candidate moves outside bounds                   | Empty edits or explicit no-available-move result; do not alter locks or claim global infeasibility                   | **Retain** lock behavior.                                                         |
| 100×100 viewport with full-size parent plus 20×20 child                | Parent makes rectangular occupied union 100%; child still contributes to box centroid if all boxes count             | **Tune** labels; 0% geometric empty area does not mean visually crowded.          |
| Duplicate identical rectangles                                         | Union occupancy unchanged; pair-overlap count and box weighting may change                                           | **Tune** multiplicity semantics; do not infer new visible content.                |
| Rectangle `x=-50,y=0,w=100,h=100` in 100×100 viewport                  | Viewport occupancy 50%; unclipped box area is 100%                                                                   | **Retain** clipped union, reject offscreen inflation.                             |
| Two 60×100 rectangles at x=0 and x=40                                  | Union 100%, overlap area 20%; summed areas 120% is not occupancy                                                     | **Retain** exact union.                                                           |
| Mere edge-touching rectangles                                          | Zero intersection area; do not count as area overlap                                                                 | **Retain** strict positive intersection test.                                     |
| Identical geometry with different arbitrary group labels               | Geometry unchanged; intra/intergroup statistics change only because the caller changed the hypothesis                | **Tune** grouping provenance.                                                     |
| RTL toolbar or vertical writing                                        | Correct authored sequence may reverse the assumed x/y traversal                                                      | **Insufficient** direction-free reading-order penalty.                            |
| Scale viewport and all rectangles by 2                                 | Absolute gaps double, occupied fractions and normalized centroid/alignment should stay invariant                     | **Retain** explicit units; do not compare absolute distances as universal scores. |
| Small vivid accent versus large muted block                            | Area centroid favors the large block, attention may favor the accent                                                 | **Discard** centroid as visual salience claim.                                    |

CSS Color 4 documents powerless hue and an OKLCH chroma epsilon of 0.000004. A larger application threshold for visually near-neutral colors is a separate modeling choice and must be labeled; it should not be represented as the CSS numerical epsilon. [CSS Color 4: powerless components and OKLCH](https://www.w3.org/TR/css-color-4/#ok-lab)

## Implementation observations

Executed nondestructive isolated probes with `node --import tsx artifacts/review/color-equations/probe-color.ts` and the corresponding `probe-composition.ts`. These import the real source modules. They neither edit production nor replace the modules' own tests. [Initial color observations](../evidence/review/color-equations/color-observations-initial.json) and [initial composition observations](../evidence/review/color-equations/composition-observations-initial.json) include SHA-256 fingerprints of the reviewed module bytes. Expectations were written by the reviewing model; they are not human ratings.

The numerical-neutral epsilon in the reviewed code is1e-6, explicitly a local precision policy. The harmony relevance cutoff is separately0.02, explicitly heuristic. Neither is represented as the CSS Color4 epsilon; all256 representable opaque gray inputs correctly receive null hue. That distinction is appropriate for the implemented narrow domain.

Composition implements a clipped **occupied-union centroid**, not the proposal's naive sum of box-area moments. Upgrade that implemented equation from **tune** to **retain** as geometry. Keep the interpretation boundary: a full-surface parent can still make the supplied geometry100% occupied even when its visual interior is largely empty. Pairwise overlap and area ranking remain multiplicity-sensitive by design, and the output states that limitation.

### Findings corrected and independently rechecked

1. **Low-priority correctness, fixed: reject a viewport whose positive dimensions multiply to zero.** Reproduction: `analyzeComposition({viewport:{width:Number.MIN_VALUE,height:Number.MIN_VALUE},rectangles:[]})`. Initial result included `whitespace.unoccupiedFraction:NaN`. The parent added a viewport-area underflow validation boundary. Independent affected-case rerun confirms both schema and analyzer now reject it; ordinary empty100×100 geometry still returns finite whitespace fraction1. **Rating: retain after correction.**
2. **Diagnostic improvement, fixed: stop when a failed role cannot change under the editable-token set.** The initial accent-only search attempted361 proposals although a failed ink/canvas pair was unchanged. The parent added `invariantFailedRoles` and an early exit. Independent rerun confirms0 attempts and0 candidates when ink/canvas are fixed; a control with ink editable still searches and finds candidates. The certificate is limited to the editable set, not global feasibility. **Rating: retain after correction.**

The focused recheck is preserved in [fix-verification.json](../evidence/review/color-equations/fix-verification.json), including final source hashes. Earlier observation files intentionally retain the pre-fix behavior and hashes; they are not presented as observations of the corrected code. This reviewer changed only this document and scratch review artifacts; the parent made the production fixes.

No hard color-arithmetic, lock, clipping, union, or ordinary-scale normalization defect was found in the executed cases. These observations support retaining the equations as scoped calculations and preference descriptors. They do not validate aesthetic rankings, a universal objective, or claims about perceived visual balance.
