# Mathematical design search and handoff review

Reviewed 2026-10-25. Scope: `src/energy.ts`, `src/math-expression.ts`, `src/decision-machine.ts`, and `src/decision-runtime.ts`. The implementation author fixed the defects below; this review added independent regression tests without changing the implementation.

The revised architecture supports cheap, brief-conditioned mathematical search and a resolved build handoff. This review does not establish repeated neural steering, learned preferences, or main-agent token savings; those require separate execution evidence. Weighted search energy expresses the declared brief and factor policy. It is separate from renderer feasibility and visual quality.

## Findings addressed

- **Mutable compiled program could invalidate its own cache identity.** The evaluator originally closed over an exposed mutable program. Deep freezing the compiled program and copying observation provenance prevent a caller from altering bands or weights while retaining the old identity.
- **Disabling the final optional factor broke serialization/replay.** Zero-weight factors now disappear before evaluation, and the normalized empty active-factor list remains a valid program. A disabled musical expression can neither affect ranking nor trigger arithmetic errors.
- **An undefined candidate aborted the whole search.** Invalid arithmetic is now recorded per attempted assignment, consumes the bounded attempt budget, and leaves valid alternatives available.
- **Machine expressions lacked structural validation.** Handoff construction now validates operator arity and all declared references, including inactive conditional branches. Missing motion references and invalid spring parameters also fail explicitly.
- **Dotted state names broke XState transitions.** Explicit state-node identifiers now keep flat semantic names distinct from XState's path syntax.
- **A rejected viewport change terminated the actor.** Invalid REFLOW requests now preserve the last valid facts, expose a rejection or search requirement, and permit a subsequent valid change.
- **Caller mutations could rewrite live actor guards.** Actor construction now owns a validated copy of the handoff.
- **Portable resolution accepted extra scenario keys.** It now checks exact scenario keys and finite values, preventing runtime input from overriding fixed or locked decisions.
- **Node and portable runtime rules diverged.** Applicability-envelope, spring-domain, and transition-expression checks now run in the shared portable resolver. A nonlinear guard or spring that is valid at calibration endpoints can fail at an interior width; that failure remains recoverable.

The tests include an independent exhaustive oracle over 27 coupled assignments; hard constraints outranking soft preferences; nonzero tension bands and multiple acceptable wells; domain deduplication and locks; identity changes; deterministic ties; numerical failures; 700 attempted states and 4,900 factor evaluations; serialized zero-selector replay; forged-recipe rejection; current-fact transition guards; invalid REFLOW recovery; portable/runtime parity; and replay invalidation when authored default/compact copy or its provenance changes. The search fixture executed without a model, renderer, network call, or native device.

The 700-state test is a small workload check, not a latency guarantee for every permitted program. The mathematical result identifies whether exhaustive coverage completed; bounded beam search does not claim a global optimum. The handoff keeps actual renderer verification pending.

## Remaining scope boundaries

- The reusable recipe is a resolved mathematical design program, assignment, and state-machine contract. It does not reuse old renderer receipts as fresh facts.
- Cache identity includes the declared program, brief, policy/runtime identity strings, machine, and assignment. Callers remain responsible for supplying accurate external version/content identities; an arbitrary font label is not a font-content digest.
- The declared scenario envelope bounds runtime applicability but does not prove every interpolated geometry is visually sound. Fresh runtime hard checks still execute; real text wrapping and platform behavior require actual rendering.
- Rejection summaries are bounded. They are diagnostic samples, not a complete persisted search tree containing every rejected branch.
- The tests establish mathematical and execution contracts, not human preference, native/browser parity, end-to-end quality, or neural-selector efficiency.
