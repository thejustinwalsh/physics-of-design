# Astra review: make the whole design system useful to builders

Synthetic review, 2026-10-25. The requested outcome is better complete Relay apps from Luna, Sol and Astra, with measured model usage and less repeated main-agent design work. This report reviews the system before those builds; it is not a result from the builds, a human preference study or an assessment of award quality.

The strongest parts should remain: real font and renderer measurements, separate hard constraints and attributed preference factors, finite numeric exploration, exact identities, retained alternatives, guarded replay and explicit native limits. The missing link is a short, reusable path from a product brief to those capabilities. The present system can move thousands of numbers cheaply while still making a builder write a large bespoke program, interpret several overlapping APIs and manufacture its own measurement/binding plumbing.

I read the complete original white paper, repository and skill instructions, the current landscape and decision architecture, the Relay brief/design/coverage contract, and relevant typography, composition, component, color, motion/material, native, validation and metrics implementations. Source identities for the inspected state are in `artifacts/astra-system-review/review-source-identities.json`. Integration work is concurrent: the findings below describe that snapshot, and closure requires new receipts. I did not edit shared implementation, run new builders or call a neural selector.

## The smallest practical product pipeline

Use five phases, with generated files and terse summaries between them. The phase state machine coordinates work; it should not become a second implementation of navigation or a requirement to model every application action as numeric design state.

1. **Freeze inputs and a platform smoke.** Inspect DESIGN once, retain exact brief/data/font/asset identities, and record source facts versus authored preferences. Predeclare the functional oracle, the two permitted web tuning rounds, review policy and required native scenarios. Builder identity and runtime versions belong in the run manifest.
2. **Measure reusable facts.** Inspect each actual font once, shape representative real UI copy, and measure the finite text candidates actually used by roles. Cache by content/font/axes/size/leading/measure/renderer, separately from DESIGN's prose identity. Browser geometry is reusable only for that browser state; native receives its own observations.
3. **Run bounded choice kernels.** Use the existing energy/workflow engine to explore coupled domains, expose tradeoffs, select a small number of meaningful frontiers, and replay unchanged stages. Retain a compact handoff of named tokens, alternatives, constraints and source-bound property bindings. Keep graphs, full measurements and audit output on disk.
4. **Build and inspect the real task.** Use shared pure relational functions and renderer adapters. The builder supplies product behavior, content structure and art direction. Measure the twelve representative surfaces plus every essential route/flow, current geometry and actual light composite. Apply one or two web tuning rounds according to the shared protocol, then run the actual native primary and secondary flows.
5. **Revalidate only affected work and report.** Changed text invalidates its measurements and dependent layout, not unrelated material arithmetic. Changed role palette invalidates relevant color/composite checks. Changed shared runtime invalidates every consuming platform receipt. Validation gates expose missing/failed/unknown evidence; a current passing receipt and explicit unsupported record have different meanings.

The main agent should decide the task hierarchy, meaningful domains and when a measured failure requires structural revision. Numeric tools should do arithmetic, feasibility, bounded exploration, sensitivity and repair. System 1 should choose only among described, admissible alternatives under the authored brief. Real renderers establish text/composite/geometry facts; functional oracles establish state behavior. Neither neural choice nor the validation coordinator substitutes for those observations.

## Reusable kernels, without a component catalog

Three reusable kernels are enough for this round. They should compile to existing `EnergyProgram` / `DecisionWorkflow` definitions, retain input identities, and produce typed outputs. A worked Relay input is shared evidence infrastructure, not a prebuilt Relay app.

| Kernel                           | Small authored input                                                                                                                               | Reused machinery and output                                                                                                                                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Measured type and row density    | Named semantic roles, actual text cells, finite font/size/leading/measure domains, row-slot minimums, target sizes and attributed preference bands | Font/typography facts plus component allocation and energy search; selected role tokens, measured consequences and row/field/toolbar anatomy. No arbitrary table typography score.                                       |
| Responsive regions               | Named regions, task priority, minimum usable measures, safe/current root, supported scenarios, permitted stack/list/detail transformations         | Existing flex/composition expressions and workflow bindings; a finite topology choice with all regions preserved, actual minimum constraints and an explicit unsupported/out-of-domain result.                           |
| Theme, finish and motion choices | Semantic color roles and state edges, light/dark variants, material candidates, common lighting regime and small named motion alternatives         | Existing palette/material/motion analysis; valid finite alternatives with intelligible aliases, measured constraints and emitted tokens/adapters. No universal sum of color, physical response and aesthetic preference. |

A helper that compiles repeated measured-table lookups, typed variable aliases and common row/region relationships is preferable to another large language or optimizer. Hard-code neither Relay's component tree nor a mandatory style. Keep values, bands and semantic priorities editable. Use Night instrument and Day instrument as real authored alternatives; do not make model tiers use different starting constraints.

The plain `composition plan` helper is useful as a proposal, but its app policy hard-codes a 220px sidebar, 460px main minimum, 310px paired minimum, 17px body and 44px controls. It has no inputs for Relay's rail/list/detail/chart-axis measures. Its output therefore cannot by itself establish dashboard topology or platform conformity. Expose the needed relationships in a bounded kernel input rather than making builders compensate through scattered overrides.

## System 1 should replace a decision, not create a ritual

The successor-lookahead correction is useful: it lets an upstream tied choice see whether downstream targets have a witnessed solution. Preserve the distinctions between exhaustive infeasibility, incomplete search and unknown branches. Retained alternatives and direct-successor bounds do not prove an all-descendant optimum.

The current selector is neither a trained taste model nor a pixel observer. The latest recorded field prompt test used approximately 2,656 and 2,183 input tokens; the earlier actual two-call CPU run took about 126 seconds. Those are narrow recorded observations. More calls are not evidence of more intelligence, and no speed advantage over the main agent follows from a small model name.

For Relay, use one readout only when a stage offers a consequential choice the model can understand. Prefer two to four broad, explicitly scoped decisions over a readout for every control or color. This is a proposed call policy, not an evidence-based optimal number. Execute deterministic repairs first. A one-option stage already bypasses inference; an equally scored frontier may still contain visually meaningful alternatives, so do not conflate a cost tie with visual equivalence. Describe what changes and what remains unmeasured.

System 1 prompts need the decision question, semantic units/aliases, brief-relevant context, a compact consequence table and the worst affected scenario. A range that combines phone and desktop can conceal the exact tradeoff. Omit repeated source prose and full graphs; retain precise references. If the selected branch fails rendering, preserve that failure, revise the shared constraint or measurement, and rerun only affected stages. Do not ask the model to certify accessibility or explain away failed hard checks.

## Meaningful tool coverage for a complete app

The Relay coverage document properly requires influence, not 61 ritual calls. Preserve it, but generate much of its ledger automatically from actual calls and bindings. Manual hashes and hand-written pass declarations increase work without establishing provenance.

Font inspection/axes/shaping should determine actual heading, row and axis roles. Palette repair should determine both themes and focus/selection/status edges. Component allocation should determine actual toolbar/row/action/field/tooltip anatomy. Composition and responsive tools should determine rail/list/detail transformation and plot bounds. Motion analysis should select a runtime-consumed retargetable interaction. Material tools should drive three intentionally different finishes under one light regime. Media analysis should affect a real diagram placement or fit. Prose analysis should affect a real task label, prerequisite or navigation decision. Wireframe inspection must attach to current elements. Validation keeps those facts current across scenarios.

A source import or a call against unrelated sample copy cannot satisfy coverage. The adapter should expose selected JSON pointer, target role/property, source location, renderer/test ID and exact identities, then compare current observed values or relationships within declared tolerances. For categorical topology, test the selected structure and preserved regions; do not pretend a number-to-string alias proves geometry. This is evidence of consumption, not a claim that a specific tool caused visual quality.

Use typed aliases for properties and regions across kernels and adapters. A typo such as a missing chart-width token should fail during validation/build rather than yielding `undefined`, `NaN`, a default style or a missing inspection overlay. The app can still use ordinary React composition and a canonical product store; a general component-state compiler is unnecessary.

## Platform and physical-material boundaries

Keep dense charts and tables on stable opaque readability layers. Material character belongs to working substrate, housing, navigation or active controls where it serves the chosen direction. Use one managed clock, stationary hit geometry, hidden/offscreen suspension, reduced-motion policy and complete disposal.

The concurrently developed GPU DOM plane is a web adapter for actual HTML content. Its implementation owner reported real pose/exposure contrast and shader-difference controls, but also a first WebKit initialization long task; this review did not rerun that evolving proof. Keep initialization optional/explicit and preserve a readable fallback. The model is isotropic GGX with directional normal texture and authored ambient fill; glass/refraction, layered cloth and anisotropy remain distinct unsupported claims. A roughness difference is not a measurement of perceptual material contrast.

Use a measured native adapter only after an actual exact-version native smoke and rendered proof. Otherwise, bind an explicit static native finish to the same semantic role. Native fallback cannot erase severity, focus, selection or the primary flow. Test actual text and safe content roots, not browser phone screenshots or nominal window dimensions. Keep iOS and Android evidence distinct.

## Fair model runs, actual usage and stopping rules

Use the requested Luna, Sol and Astra families with exact available model IDs and resolved effort recorded before construction. A CLI that offers an older Luna/Sol than the native collaboration tool is a material experiment setting. Do not silently label different versions equivalent or infer per-agent usage from account limits. If model availability prevents the requested configuration, report the exact limitation before calling the comparison matched.

The app-server helper is the best current route to incremental actual usage. Set `timeoutMs:null` for the user's unbounded wall-time request, keep cancellation working, and regression-test that path. Before the long builders, complete one tiny real authorized turn for each chosen model/transport, confirming actual model identity, usage notifications and final completion. A schema or handshake alone cannot prove the notification path. These are transport qualification probes, not extra Relay builders.

Retain raw events and the latest cumulative `total`, with input, cached input, output and reasoning counters exactly as reported. Never sum successive totals or add cached/reasoning fields twice. Include bootstrap, discovery, implementation, testing, self-critique and repair usage in each builder's run scope. Report preparation and shared tool development separately. No notification means unknown; interruption preserves the last reported cumulative usage with its unreported tail caveat. The helper's observed final turn and latest usage remain different facts.

Before launching the three builders, stop for any unresolved runtime-band mismatch, unsupported required platform setup, missing alias/binding checks, invalid shared fixture, non-working usage stream, or unrecorded model substitution. After launch, stop a stage on exhausted numeric/readout budgets, no witnessed required continuation, stale inputs or a failed required renderer check. Unbounded wall time does not authorize infinite search or silently revised requirements.

Evaluate each complete primary flow against the frozen data oracle first, then responsive/interaction/visual criteria. Keep self-critique as a separately labeled synthetic report with concrete observed failures, fixes, remaining issues and referenced screenshots/receipts. An independent review can check the same frozen outcomes; it should not give one builder extra design coaching. Equal allowed tuning rounds and feedback matter more than equal elapsed time. Compare raw usage and quality dimensions directly; three models on one app cannot establish universal toolkit efficiency, and an improvement over another model is not an ablation of toolkit use.

## Review limits and closure

The initial review established one executed runtime defect, one executed selector-information gap and measured context-size/authoring-cost observations. The implementation closure below adds a bounded kernel and binding proof; neither establishes end-to-end builder efficiency, the quality of future Relay builds, human preference, physical-device power or trained selector competence. Routing documents must reflect the final implementation, preserving old reports as historical rather than rewriting their results.

Acceptance is concrete: implement the ranked corrections, execute the indicated negative controls and a current ordered verification lane, freeze the shared setup, then run the three builders. Do not spend the experiment budget building a general app compiler, a new aesthetic objective, a new trained judge, automatic recursive search or a component catalog. The proposed improvement is less bespoke authoring, smaller visible context, meaningful local decisions and verifiable consumption of the decisions already made.
