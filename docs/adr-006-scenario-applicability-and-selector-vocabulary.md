# ADR 006: scenario applicability and selector vocabulary

Status: implemented; actual model and native renderer revalidation belongs to the subsequent proof run. This change follows the two blockers in the [independent system review](astra-system-effectiveness-review.md).

The review reproduced a compiler/runtime contradiction: a named enlarged-text hard band passed `compileEnergy`, but the portable resolver applied the default band and rejected the same assignment. It also found that the selector saw numeric `motionRole` assignments without their Quiet, Settle, and Rebound meanings or units. Both errors changed the meaning of a choice after its mathematical evaluation.

`resolveDesignRuntime`, trusted handoff resolution, XState actor creation and REFLOW, and handoff replay now share scenario applicability. An optional `scenarioId` must name a declared scenario whose complete numeric input vector exactly equals the actual inputs. Without an ID, a unique exact match resolves automatically. Multiple exact matches are usable only when their effective bands agree; divergent bands fail closed until the caller names the intended matching scenario. Bands are never selected by nearest viewport or interpolation.

At an unsampled continuous input, an overridden hard factor is unresolved and makes the result inadmissible. A handoff can explicitly author `runtimePolicy: { unsampledScenarioBands: 'base' }` to use default bands there; this policy is included in handoff identity and does not expand the declared input envelope. Preference-only overrides remain visibly unresolved at unsampled inputs, while independent resolved hard guards can still admit geometry. Programs without overrides retain continuous evaluation inside their declared envelope. Renderer verification remains pending in every case.

Handoffs retain their version-1 envelope and add `runtimeSemantics: 'scenario-bands-v2'` to the hashed body. Previous receipts therefore invalidate instead of silently claiming the revised execution semantics. Replay takes the optional policy as an authored input and re-evaluates the current scenario with zero search and zero selector calls. Actor reflow rejects mismatched IDs and preserves the last valid facts so a later valid reflow can recover.

Energy variables can now carry optional bounded `label` and `valueAliases: [{ value, label }]` metadata. If provided, aliases must cover each distinct domain value exactly once, with no unknown values or duplicate labels. Canonical alias order follows numeric value. Labels, units, and aliases are included in program identity; they do not change factor costs. The field compiler uses the portable `DESIGN_FIELD_MOTION_ROLES` dictionary in `src/design-field-vocabulary.ts`; UI consumers can import that same dictionary instead of maintaining a separate mapping.

The local-selector payload includes a variable dictionary once per prompt, plus successor dictionaries when lookahead is present. Each option summarizes at most 12 preference factors, ordered by largest worst-scenario normalized residual; an explicit omitted count records truncation. A row retains the value range, worst scenario, residual, applicable target bands, known direct-reference units, and provenance kind. Full factor rows and source strings remain in the receipt. Successor summaries use the same bounded representation. The selector cache policy includes `units-aliases-worst-scenario-v2`, so prior prompts cannot replay as the new semantic payload.

Validation on 2026-10-25:

- The original synthetic runtime probe now returns compiler hard failures 0, portable admissible true, and actor accepted. Historical failure and corrected receipt remain in `artifacts/astra-system-review/scenario-bands-runtime.json` and `scenario-bands-runtime-fixed.json`.
- Focused tests cover permissive and restrictive overrides, explicit-ID mismatch, duplicate-vector ambiguity, continuous policy identity, actor recovery, portable/trusted/replay parity, alias completeness and invalidation, and bounded worst-scenario summaries.
- A fresh no-model Chromium proof in `artifacts/design-field-runtime-v2` measured 252 cells and passed all six finalist scenarios. It evaluated 3,132 assignments including 2,592 lookahead evaluations, selected an expression with zero authored preference residual, and replayed with zero searches and zero model calls. Six saved successor alternatives were freshly revalidated. The compact session is 1,594,982 bytes.
- Tokenizer-only encoding through the installed Qwen3.5 direct-readout template used 4,506 reading tokens and 3,733 expression tokens under the 8,192-token limit, with six answer slots per stage and zero model forward calls. Raw inputs, source bindings, and token counts are in `artifacts/astra-system-review/selector-vocabulary-*.json`. These counts do not demonstrate model decision quality.

`scripts/prove-design-field.mjs` now records source and executed-module hashes before measurements, search, or inference, then requires the same hashes before writing final receipts or publishing a fixture. Its `implementation-freeze.json` distinguishes a running or interrupted proof from a verified unchanged run. This prevents a long proof from binding its receipt to source edits made after execution started; the fresh proof passed this check. Native implementation identity changed, and the earlier actual model receipt used the ambiguous vocabulary. Both require fresh downstream verification before being described as current.
